Every error response has the same shape:

```json title="Error shape"
{
  "error": "Human-readable message",
  "code": "machine_readable_code"
}
```

Validation errors (422) and parameter errors (400) include per-field detail:

```json title="Validation error shape"
{
  "error": "Validation failed",
  "code": "validation_error",
  "details": {
    "fieldErrors": { "url": ["URL must use HTTPS"] },
    "formErrors": ["At least one of status or rank must be provided"]
  }
}
```

Always check `code` in your error handler — the `error` message is for humans and may change between versions.

## Handling errors in code

<Aside type="tip">
  Always handle `400`, `401`, `404`, `409`, and `429` explicitly. Everything else can fall through to a generic error handler.
</Aside>

```ts title="TypeScript error handler"
async function apiFetch(path: string, init?: RequestInit) {
  const res = await fetch(`https://app.feediyo.com/v1${path}`, {
    ...init,
    headers: {
      Authorization: `Bearer ${process.env.FEEDIYO_API_KEY}`,
      'Content-Type': 'application/json',
      ...init?.headers,
    },
  });

  if (res.ok) return res.json();

  const body = await res.json().catch(() => ({}));
  const code = body.code ?? 'unknown';

  switch (res.status) {
    case 400: throw new Error(`Bad request: ${code} — ${JSON.stringify(body.details ?? {})}`);
    case 401: throw new Error(`Auth failed: ${code}`);
    case 404: throw new Error(`Not found: ${code}`);
    case 409: throw new Error(`Conflict: ${code}`);
    case 422: throw new Error(`Validation: ${JSON.stringify(body.details)}`);
    case 429: {
      const wait = Number(res.headers.get('Retry-After') ?? 30);
      throw new Error(`Rate limited — retry after ${wait}s`);
    }
    default: throw new Error(`API error ${res.status}: ${body.error}`);
  }
}
```
