Every time a post's status is updated in Feediyo, an immutable audit record is created. This endpoint exposes that history — useful for reporting, timeline views, and integration sync.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| <span class="badge-method badge-get">GET</span> | `/v1/posts/:id/status-changes` | List status changes for a post |

---

## List status changes

<div class="endpoint-url"><span class="badge-method badge-get">GET</span><code>/v1/posts/:id/status-changes</code></div>

Returns status change events in reverse-chronological order (newest first).

### Parameters

| Name | In | Type | Required | Description |
|------|----|------|----------|-------------|
| `id` | path | string | Yes | Post ID |
| `limit` | query | integer | No | Page size — default `25`, max `100` |
| `cursor` | query | string | No | Pagination cursor from previous response |

### Request

<Tabs>
  <TabItem label="curl">
    ```bash
    curl "https://app.feediyo.com/v1/posts/post_01xyz789/status-changes?limit=25" \
      -H "Authorization: Bearer YOUR_KEY"
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```ts
    const res = await fetch(
      'https://app.feediyo.com/v1/posts/post_01xyz789/status-changes?limit=25',
      { headers: { Authorization: 'Bearer YOUR_KEY' } },
    );
    const { data, hasMore, cursor } = await res.json();
    ```
  </TabItem>
</Tabs>

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `id` | string | No | Unique activity record ID |
| `postId` | string | No | Post this change belongs to |
| `oldStatus` | string | Yes | Status before the change. `null` for the initial creation record. |
| `newStatus` | string | No | Status after the change |
| `changedById` | string | Yes | Profile ID of the user who made the change. `null` if the user was later deleted. |
| `changedByName` | string | Yes | Display name at time of lookup. `null` if the user was deleted. |
| `createdAt` | string | No | ISO 8601 timestamp of the change |

<Aside type="note">
  `changedById` and `changedByName` are intentionally nullable. Feediyo preserves audit records even after a user is deleted — the change is recorded, but the actor is no longer resolvable.
</Aside>
