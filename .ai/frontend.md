# Frontend Rules

## Component Location

| Component type | Location |
|---------------|----------|
| shadcn primitives | `components/ui/` |
| App layout (sidebar, nav, header) | `components/layout/` |
| Shared cross-feature | `components/shared/` |
| Feature-specific | `features/<name>/components/` |

Never put domain-specific UI in `components/ui/` or `components/layout/`.

## Component Rules

- One component per file
- Prefer named exports over default exports for components (easier to refactor)
- No business logic in components — call hooks or pass handlers as props
- No direct DB/fetch calls inside components — use loaders/actions via React Router

## Refs — React 19

This project runs React 19. **Never use `forwardRef`** — pass `ref` as a plain prop directly.

```tsx
// Bad — forwardRef is unnecessary in React 19
const Input = forwardRef<HTMLInputElement, InputProps>(({ className, ...props }, ref) => (
  <input ref={ref} className={cn("...", className)} {...props} />
))

// Good — ref is just a prop
function Input({ ref, className, ...props }: InputProps & { ref?: React.Ref<HTMLInputElement> }) {
  return <input ref={ref} className={cn("...", className)} {...props} />
}
```

The existing `components/ui/` files (dialog, popover, sheet, tabs) still use `forwardRef` — they were generated by shadcn before React 19. Migrate them when you touch them, don't leave new ones in that pattern.

## Route Loaders and Actions

Loaders and actions are the data layer for UI. Keep them thin:

```ts
// route file
export async function loader({ request, params }: Route.LoaderArgs) {
  return loadFeedbackPageData({ request, params })  // delegate to feature
}

export default function FeedbackPage() {
  const { posts, board } = useLoaderData<typeof loader>()
  return <FeedbackList posts={posts} board={board} />
}
```

## Forms

Use React Router's `<Form>` + `useFetcher` pattern. Validate with Zod on both client (for UX) and server (for security).


## Hooks

Feature-specific hooks live in `features/<name>/hooks/`.
Global hooks (auth, theme, permissions) live in `app/hooks/`.

Hook naming: always prefix with `use`.

## State Management

Prefer:
1. URL state (search params) for shareable/bookmarkable state
2. React Router loader data for server state
3. React local state (`useState`) for ephemeral UI state
4. Zustand (if in use) only for truly global client state

Avoid prop drilling more than 2 levels — extract a context or a hook.

## Styling

- Tailwind utility classes only — no custom CSS unless unavoidable
- Use `cn()` (clsx/tailwind-merge) for conditional classes
- Follow shadcn/ui patterns for component variants
- No inline `style` props except for dynamic values that can't be expressed in Tailwind
