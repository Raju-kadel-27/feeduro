Every request must include a valid API key in the `Authorization` header as a Bearer token.

```http title="Required header"
Authorization: Bearer YOUR_API_KEY
```

## Creating an API key

1. Open your Feediyo workspace.
2. Go to **Settings → API Keys**.
3. Click **Create key**, give it a name, and copy the value — it is shown **only once**.

## Making an authenticated request

<Tabs>
  <TabItem label="curl">
    ```bash
    curl https://app.feediyo.com/v1/boards \
      -H "Authorization: Bearer fdy_live_xxxxxxxxxxxx"
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```ts
    const response = await fetch('https://app.feediyo.com/v1/boards', {
      headers: {
        Authorization: 'Bearer fdy_live_xxxxxxxxxxxx',
      },
    });

    const { data } = await response.json();
    ```
  </TabItem>
</Tabs>

## Error responses

**Missing or malformed header**

```json title="401 Unauthorized"
{
  "error": "Missing or invalid Authorization header",
  "code": "missing_api_key"
}
```

**Key not found, disabled, or expired**

```json title="401 Unauthorized"
{
  "error": "Invalid or expired API key",
  "code": "invalid_api_key"
}
```

## Key scoping

API keys are scoped to a **single organization**. All data returned is scoped to that org — cross-tenant access is not possible regardless of which key you use.

<Aside type="caution">
  Treat your API key like a password. Never expose it in client-side JavaScript or commit it to source control. Use environment variables.
</Aside>
